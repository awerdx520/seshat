# ADR-002：LLM 混合后端架构（云端 API + 本地处理节点）

## 状态
已接受（2026-10-11）

## 背景
服务端需引入 LLM 能力：文档解析分析、笔记错误/引用审查、阅读行为分析、遗忘性复习（间隔重复）、归纳总结。云 VPS 无 GPU/强算力，无法部署本地模型（Ollama），需借助本地处理节点提供本地模型能力。

## 决策
采用混合后端：
1. 统一 LLM 抽象层（统一接口 + 可配置路由规则）。
2. 云端 API（DeepSeek）：VPS 直接调用，处理一般/复杂任务。
3. 本地处理节点（家庭机器/NAS 跑 Ollama）：作为纯推理节点，通过服务端任务队列接收任务 → 本地推理 → 结果明文回传服务端。
4. 所有数据统一静态加密（SQLCipher/LUKS，服务端可读明文），无 E2EE。
5. 路由默认云端；需本地模型的任务（隐私敏感/本地模型擅长）走本地节点。

## 理由
- 云 VPS 无算力，无法本地部署 Ollama。
- 纯云端：隐私风险（个人笔记上云）。
- 本地节点提供本地模型能力（隐私/离线/成本），且作为纯推理节点，无需引入 E2EE 复杂度。

## 替代方案
- 纯云端 API：隐私风险，部分放弃。
- 本地节点 + 敏感数据 E2EE：密钥分发/索引/合并复杂度高，经用户决定放弃。

## 后果
- 正面：本地模型能力可用、隐私可控、无 E2EE 复杂度。
- 负面：需维护本地节点 worker + 任务队列；本地节点需常开。
