## 目标

补齐 PDF 阅读器剩余三项能力，且不破坏 M9.2 已建立的渲染管线（单线程后台渲染 + LRU 缓存 + 双翻页模式）：

1. **手写批注**：在页面位上自由绘制笔迹，支持撤销上一笔、清除本页；笔迹**仅存本地**（`PdfInkStore`），`location` 的 ink 协议写入文档但**不接入服务端同步**（留给 M10.3 统一批注同步）。
2. **点击翻页**：横向模式下点击左右区域翻页、中间区域切换工具栏；竖向模式下点击只切换工具栏。
3. **横屏适配**：横向翻页在横屏时按可用高度计算渲染宽度（减少留白、提升有效分辨率）；底部工具栏改为浮层，不挤占阅读区。

可机械判定的验收标准：

1. `cd android && ./gradlew :app:assembleDebug` 成功（L1）。
2. `cd android && ./gradlew :app:testDebugUnitTest` 全绿，用例总数 ≥ 246（既有 225 + 新增 ≥21：`InkGeometryTest` ≥11、`PdfInkStoreTest` ≥11）（L2）。
3. `aapt2 dump badging` / `apkanalyzer manifest print` 静态校验：包名不变、5 个 Activity 齐全（L3 降级）。
4. 人工真机验收 8 项（见「验证标准」）。

## 设计

### 1. 数据模型（新增 `reader/PdfInkAnnotation.kt`）

```kotlin
/** 归一化坐标点（相对页面显示矩形的 0..1）。 */
@Serializable
data class InkPoint(val x: Float, val y: Float)

/** 一笔笔迹：颜色、归一化线宽（相对页宽 0..1）、归一化点序列。 */
@Serializable
data class InkStroke(
    val color: Int,
    val width: Float,
    val points: List<InkPoint>,
)

/** 单页的笔迹集合。 */
@Serializable
data class PdfInkPage(val page: Int, val strokes: List<InkStroke>)

/** 单个文档的全部手写笔迹（按页组织）。 */
@Serializable
data class PdfInkDocument(
    val documentId: String,
    val pages: List<PdfInkPage> = emptyList(),
    val updatedAt: Long = 0L,
)
```

- 坐标**归一化 0..1**：跨横竖屏、跨 `renderWidth`、跨缩放都无需迁移数据。
- `width` 也归一化（相对页宽），绘制时 `px = width × 显示矩形宽`，保证不同分辨率下线宽视觉一致。
- 页号用 **0-based**，与 `PdfProgress.page` 以及 `firstVisiblePage()` 一致；仅在展示给用户时 +1。

### 1.1 ink 的 `location` 协议（本次仅写文档，不上传）

`docs/api.md` 4.5 节新增下面格式，与既有 `page:<n>;rect:...` **同字段共存**，靠 `;rect:` / `;ink:` 前缀区分（服务端始终按不透明字符串处理，不解析）：

```
page:<n>;ink:<color>,<widthPt>,<x0>,<y0>,<x1>,<y1>,...
```

- **一笔一个 annotation**（笔迹过长时分条，便于单笔删除）。
- `color`：`#AARRGGBB`（如 `#FFE53935`）。
- `widthPt`：线宽，**PDF point 空间**，两位小数。
- 点序列：页面坐标（PDF point、原点左上、y 轴向下），两位小数——与 `rect` 同口径。
- **口径转换（本地 → 协议）**：本地存归一化坐标（相对显示矩形），同步时按
  `x_pt = nx × page.width`、`y_pt = ny × page.height`、`width_pt = width × page.width` 转换。
- 本次**只写文档、不实现上传**：Android 侧批注同步 UI 尚未建立；Emacs 端只支持 `rect`，无法渲染笔迹。

### 2. 存储（新增 `reader/PdfInkStore.kt`）

```kotlin
class PdfInkStore(
    private val read: (String) -> String?,
    private val write: (String, String) -> Unit,
    private val json: Json = defaultJson(),
) {
    fun document(docId: String): PdfInkDocument
    fun strokes(docId: String, page: Int): List<InkStroke>
    fun hasInk(docId: String, page: Int): Boolean
    fun count(docId: String): Int
    fun appendStroke(docId: String, page: Int, stroke: InkStroke)
    /** 撤销该页最后一笔；无笔迹时返回 false。 */
    fun undoLast(docId: String, page: Int): Boolean
    /** 清除该页全部笔迹。 */
    fun clearPage(docId: String, page: Int)

    companion object {
        const val PREFS_NAME = "pdf_reader"   // 与 PdfAnnotationStore / PdfProgressStore 共用文件，键空间隔离
        fun key(docId: String): String = "pdf_ink_$docId"
        fun defaultJson(): Json = Json { ignoreUnknownKeys = true; encodeDefaults = true }
    }
}
```

- `pages` 用 `List<PdfInkPage>` 而非 `Map<Int, ...>`（kotlinx.serialization 的 JSON map key 只支持字符串）。
- JSON 损坏时返回空文档（`runCatching`），不抛异常。
- 每次写入都 `updatedAt = System.currentTimeMillis()`。

### 3. 坐标换算（新增 `reader/InkGeometry.kt`，**纯逻辑无 Android 依赖**）

```kotlin
object InkGeometry {
    /** 计算 FIT_CENTER 下图片在 View 内的显示矩形（dx/dy 为居中留白）。 */
    fun fitCenterRect(viewWidth: Int, viewHeight: Int, imageWidth: Int, imageHeight: Int): RectF

    /** 像素（相对 View）→ 归一化（相对显示矩形），越界夹紧到 0..1。 */
    fun toNormalized(px: Float, py: Float, rect: RectF): InkPoint

    /** 归一化 → 像素（相对 View）。 */
    fun toDisplay(point: InkPoint, rect: RectF): PointF

    /** 归一化线宽 → 像素。 */
    fun strokeWidthToPx(normalized: Float, rect: RectF): Float
}
```

**数值示例（实施与测试都用它自检）**：
- 例 1：`view 1000×800`、`image 500×800` → `scale = min(1000/500, 800/800) = 1.0` → 显示矩形 `left=250, top=0, right=750, bottom=800`。
  - `toDisplay(InkPoint(0.5f, 0.5f), rect)` = `(500, 400)`。
  - `toNormalized(500f, 400f, rect)` = `(0.5f, 0.5f)`。
- 例 2：`view 1000×800`、`image 2000×800` → `scale = min(0.5, 1.0) = 0.5` → 显示矩形 `left=0, top=200, right=1000, bottom=600`。
  - `toNormalized(0f, 200f, rect)` = `(0.0f, 0.0f)`；`toNormalized(1000f, 600f, rect)` = `(1.0f, 1.0f)`。
- 例 3：越界点 `toNormalized(-50f, 900f, rect)`（rect 同例 1）→ `(0.0f, 1.0f)`。
- 例 4：`strokeWidthToPx(0.01f, rect 例 1)` = `0.01 × 500 = 5.0f`。

**注意**：`RectF` 来自 `android.graphics`，会让该类变成 Android 依赖 → 为保持 JVM 可测，**改用自定义数据类**：
```kotlin
/** 图片在 View 内的显示矩形（避免依赖 android.graphics.RectF，保持纯 JVM 可测）。 */
data class DisplayRect(val left: Float, val top: Float, val width: Float, val height: Float)
```
所有方法用 `DisplayRect`，由调用方（`InkOverlayView`）用 `ImageView.imageMatrix` 或自算转换。

### 4. 绘制与触摸（新增 `reader/InkOverlayView.kt`）

- `class InkOverlayView(context: Context) : View(context)`，覆盖在 `ImageView` 之上。
- 属性：
  - `fun setStrokes(strokes: List<InkStroke>)`（触发 `invalidate()`）
  - `fun setImageSize(width: Int, height: Int)`（用于算 `fitCenterRect`）
  - `fun setInkEnabled(enabled: Boolean)`
  - `var onStrokeFinished: ((InkStroke) -> Unit)?`
  - `fun undoLastLocal()` / `fun clearLocal()`（供 Activity 即时刷新，不必等重新绑定）
- `onDraw`：`val rect = InkGeometry.fitCenterRect(width, height, imageW, imageH)`；对每条 stroke 构造 `Path`（`toDisplay` 转换每点），`paint.strokeWidth = InkGeometry.strokeWidthToPx(stroke.width, rect)`、`strokeCap = ROUND`、`strokeJoin = ROUND`、`style = STROKE`。
- `onTouchEvent`：
  - `!inkEnabled` → 返回 `false`（事件交给 RecyclerView）。
  - `ACTION_DOWN` → `parent.requestDisallowInterceptTouchEvent(true)`；新建当前笔（颜色/线宽取默认）；落点。
  - `ACTION_MOVE` → 追加点（距上点 > 1px 才加，降采样）；`invalidate()`。
  - `ACTION_UP`/`ACTION_CANCEL` → 若点数 ≥2，构造 `InkStroke` 并回调 `onStrokeFinished`；清空当前笔；`parent.requestDisallowInterceptTouchEvent(false)`。
  - 返回 `true` 消费事件。
- 默认样式常量：`DEFAULT_COLOR = 0xFFE53935.toInt()`（红）、`DEFAULT_WIDTH_NORMALIZED = 0.004f`。
- 触摸落点必须先换算到归一化：`InkGeometry.toNormalized(event.x, event.y, rect)`。

### 5. Adapter 改造（`reader/PdfPageAdapter.kt`）

- item 根改为 `FrameLayout`（即 `itemView`），内含 `ImageView` + `InkOverlayView`，两个子 View 均 `MATCH_PARENT × MATCH_PARENT`。
- **LayoutParams 必须迁到 `FrameLayout`（`itemView`）上**——M9.2 里页高写在 `ImageView` 上，改结构后若不迁移，竖向连续滚动的高度会失效：
  - `onCreateViewHolder`：横向 → `MATCH_PARENT × MATCH_PARENT`；竖向 → `MATCH_PARENT × WRAP_CONTENT`。
  - `onBindViewHolder`（竖向）：`holder.itemView.layoutParams = (holder.itemView.layoutParams).also { it.height = pageHeights[position] }` + `holder.itemView.requestLayout()`；`pageHeights[position] == 0`（尚未算好）时保留屏高占位，避免 item 高度塌陷为 0。
- 构造增加 `private val inkHost: PdfInkHost`：
```kotlin
/** PDF 手写层的宿主回调。 */
interface PdfInkHost {
    /** 该页已有的笔迹。 */
    fun inkStrokes(page: Int): List<InkStroke>
    /** 一笔完成（宿主负责持久化）。 */
    fun onInkStrokeFinished(page: Int, stroke: InkStroke)
    /** 当前是否处于手写模式。 */
    fun isInkEnabled(): Boolean
}
```
- `onBindViewHolder` 额外设置手写层：`overlay.setImageSize(bitmap.width, bitmap.height)`（`bitmap` 宽 = `renderWidth`、高 = 比例高，正是 FIT_CENTER 的固有尺寸）、`overlay.setStrokes(inkHost.inkStrokes(position))`、`overlay.setInkEnabled(inkHost.isInkEnabled())`、`overlay.onStrokeFinished = { stroke -> inkHost.onInkStrokeFinished(position, stroke) }`。
- **`setInkEnabled(enabled)` 的可达写法**（Adapter 本身没有 RecyclerView，必须缓存引用）：
```kotlin
    /** 覆盖此方法缓存 RecyclerView，供 setInkEnabled 定位可见 item。 */
    override fun onAttachedToRecyclerView(recyclerView: RecyclerView) {
        super.onAttachedToRecyclerView(recyclerView)
        this.recyclerViewRef = WeakReference(recyclerView)
    }

    /** 切换手写模式：只刷新当前可见 item 的 overlay，避免整列表重绑导致图片闪烁。 */
    fun setInkEnabled(enabled: Boolean) {
        inkEnabled = enabled
        val rv = recyclerViewRef?.get() ?: return
        val lm = rv.layoutManager as? LinearLayoutManager ?: return
        val first = lm.findFirstVisibleItemPosition()
        val last = lm.findLastVisibleItemPosition()
        if (first == RecyclerView.NO_POSITION || last == RecyclerView.NO_POSITION) return
        for (i in first..last) {
            val holder = rv.findViewHolderForAdapterPosition(i) as? PageViewHolder ?: continue
            holder.overlay.setInkEnabled(enabled)
        }
    }
```
  并新增字段 `private var recyclerViewRef: WeakReference<RecyclerView>? = null`、`private var inkEnabled = false`（`onBindViewHolder` 用它兜底新绑定项）。

### 6. 交互（`reader/PdfReaderActivity.kt`）

- 新增状态：`private var inkEnabled = false`（经 `onSaveInstanceState` 以键 `state_ink_enabled` 保存/恢复）；`private lateinit var inkStore: PdfInkStore`。
- Activity 实现 `PdfInkHost`：`inkStrokes(page) = inkStore.strokes(docId, page)`；`onInkStrokeFinished(page, stroke) = inkStore.appendStroke(docId, page, stroke)`；`isInkEnabled() = inkEnabled`。
- 浮层工具栏按钮：
  - `pdfInkToggleButton`：「手写」开关；开 → `inkEnabled = true; adapter.setInkEnabled(true)`，关 → 反之。
  - `pdfInkUndoButton`：「撤销」→ `inkStore.undoLast(docId, firstVisiblePage())`，成功则刷新该页 overlay（`adapter.refreshInk(firstVisiblePage())`，Adapter 新增方法：取该页可见 holder 的 overlay 重新 `setStrokes`）。
  - `pdfInkClearButton`：「清除本页」→ `inkStore.clearPage(...)` + 刷新。
  - `pdfPrevPageButton` / `pdfNextPageButton`：**仅在手写模式可见**（手写时点击与滑动都被落笔占用，必须保留翻页手段）。
  - `pdfAddAnnotation`（文本批注）保留。
- **点击翻页**：`recycler.addOnItemTouchListener` + `GestureDetector`：
  - `onInterceptTouchEvent` 里调用 `gestureDetector.onTouchEvent(e)` 后**恒返回 `false`**——绝不拦截事件，保证滑动与 `PagerSnapHelper` 吸附照常。
  - 翻页只发生在 `onSingleTapUp` 回调内：
    - `inkEnabled` → 直接返回（落笔优先）。
    - 横向模式：`event.x < width * 0.3` → `movePage(-1)`；`> width * 0.7` → `movePage(+1)`；否则 `toggleChrome()`。
    - 竖向模式：任意位置 → `toggleChrome()`。
  - `movePage(delta)`：`target = (firstVisiblePage() + delta).coerceIn(0, lastPage)`；**用 `recycler.scrollToPosition(target)`（立即跳转）**，避免与 `PagerSnapHelper` 的 smooth 动画竞争；若 `target == firstVisiblePage()` 则不动。
  - `toggleChrome()`：切换浮层工具栏（含页码指示）的 `visibility`。

### 7. 横屏适配

- `renderWidth()` 改为 `renderWidth(renderer: PdfRenderer): Int`：
  - 竖向模式，或竖屏（`widthPixels <= heightPixels`）→ 返回 `widthPixels`。
  - 横屏 + 横向模式 → 主线程一次性 `renderer.openPage(0).use { page -> ... }` 读首页宽高比，`candidate = ((heightPixels * 0.92f) * page.width / page.height).toInt()`，返回 `min(candidate, widthPixels)`。
  - **调用时机必须在 `PdfPageAdapter` 构造之前**（此时 `renderExecutor` 尚未创建，与 M9.2 的单线程渲染不冲突；`openPage` 不渲染、耗时 <5ms）。
  - **已知假设**：用首页宽高比代表全书；混合横竖页面的 PDF 非首页可能非最优（记入 tech-debt）。
- 布局 `activity_pdf_reader.xml` 改为 `FrameLayout`：`RecyclerView` 铺满 `match_parent`；浮层工具栏 `layout_gravity="bottom"`、背景 `#CC000000`、`android:fitsSystemWindows="true"`，并在代码里按 `WindowInsetsCompat` 给底部补 padding（避免被系统导航栏遮挡）。
- 旋转：Activity 重建 → 新 `renderWidth` → 重渲染；进度经 `scrollToPosition` 恢复；`inkEnabled` 经 `onSaveInstanceState` 恢复；笔迹因归一化天然对齐。

## 注意事项

- **TDD 强制**：T1 的两个测试必须先写并见红，再写实现。
- **`InkGeometry` 必须纯 JVM**：不得 import `android.graphics.RectF`（用自定义 `DisplayRect`），否则单测跑不了。
- **坐标口径**：笔迹点一律**归一化 0..1（相对图片显示矩形）**；像素只在绘制/触摸瞬间出现，且必须经 `InkGeometry` 换算。
- **`FIT_CENTER` 留白**：横向模式 item 高 = 屏幕高、图片左右有留白；`InkOverlayView` 必须用 `fitCenterRect` 算显示矩形，不能直接用 View 尺寸。
- **手势优先级**：手写模式下 `InkOverlayView` 必须 `requestDisallowInterceptTouchEvent(true)`，否则 RecyclerView 会抢走拖动（画不了直线）。
- **`onInterceptTouchEvent` 恒返回 `false`**：只把事件喂给 `GestureDetector`，绝不拦截；否则会吞掉滑动与 `PagerSnapHelper` 吸附。翻页动作只在 `onSingleTapUp` 里执行。
- **竖向页高必须写在 `itemView`**：item 根改 `FrameLayout` 后，`pageHeights` 写回到 `holder.itemView.layoutParams.height` 并 `requestLayout()`；写在 ImageView 上会导致竖向连续滚动高度失效。
- **`PdfRenderer` 单线程**：`renderWidth(renderer)` 里读首页尺寸是**构造 Adapter 之前**的一次性主线程 `openPage(0)`（不渲染、<5ms）；构造之后所有 renderer 访问必须回到渲染线程。
- **手写模式必须保留翻页手段**：手写时点击与滑动都被落笔占用，浮层必须显示「上一页 / 下一页」按钮。
- **`inkEnabled` 要持久化到 `savedInstanceState`**，否则旋转后手写开关状态丢失。
- **翻页用 `scrollToPosition`**（无动画），避免与 `PagerSnapHelper` 的 smooth 动画竞争；连点不会累积。
- **浮层 toolbar**：`android:fitsSystemWindows="true"` + 代码按 `WindowInsetsCompat` 补底部 padding，避免被导航栏/刘海遮挡。
- **字符串前缀**：`pdf_ink_*` / `pdf_prev_page` / `pdf_next_page`；不与既有 `pdf_*` 冲突。
- **零新增依赖**：笔迹用 `android.graphics.Path` + `Canvas`，不引入第三方绘图库。
- **不破坏 M9.2 不变量**：单线程渲染、LRU 缓存、`bindingAdapterPosition` 校验、`shutdownNow()` 全部保留。
- **验证边界**：T2–T4 无 JVM 单测（自定义 View、RecyclerView、GestureDetector、displayMetrics 均无法在 JVM 跑），依赖 L1 编译 + 人工真机验收；已在 tech-debt 记录「无设备验证手写对齐」。
- **不得读取** `android/keystore.properties` / `release.keystore` / `data/secrets.env`。
