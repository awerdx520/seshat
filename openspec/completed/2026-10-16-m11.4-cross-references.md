## 背景

阅读（seshat-reader）与笔记（denote org）是两个互不感知的子系统，唯一的桥是批注的 `document_id`。M11.3 已让「能取到文本」变成「能存住批注」，但**阅读所得无法沉淀进笔记，笔记中对某本书的论断也无法回溯到出处**。

本步建立一条可逆、可机械解析的引用通道，且**不依赖尚未实现的服务端基础设施（M7 的 uid/refs/resolve 均未开工）**。

## 目标

1. 定义并落地 **`seshat:` 链接协议**（`seshat:<doc-id>#<location>`），支持构造、解析与 `org-link-set-parameters` 注册；
2. **阅读器 → 笔记**：把选区文本（或当前页）与来源链接组装为摘录块，追加到指定笔记文件；
3. **笔记 → 阅读器**：`C-c C-o` / `org-open-at-point-global` 跟随链接，打开本地电子书并跳到对应页（复用已有 reader buffer，避免重复 buffer）；
4. **批注列表 → 笔记**：对列表中当前行批注生成引用（含批注正文 + 来源链接）；
5. `M-x org-store-link` 在阅读器中直接生成 `seshat:` 链接；
6. 服务端**零改动**；不引入第三方依赖；vendor 边界不破（不改 vendored 文件）。

## 设计

### 链接协议（核心）

**格式**：`seshat:<doc-id>#<location>`，`#<location>` 可省略。

| 语义 | 示例 |
|---|---|
| 整本书 | `seshat:ebook:d2l-zh-pytorch.pdf` |
| 某页 | `seshat:ebook:d2l-zh-pytorch.pdf#page:112` |
| 某区域（批注级） | `seshat:ebook:d2l-zh-pytorch.pdf#page:112;rect:50.00,100.00,545.00,140.00` |
| 本地未配置根的文档 | `seshat:local:/abs/path.pdf#page:3` |

**解析规则**：剥 `seshat:` 前缀 → 取**最后一个** `#` 分割为 doc-id 与 location；location 段复用既有 `page:` 语义。**不做任何百分号转义**：禁用 `url-hexify-string`（它会把 `:`、`/` 一并转义，破坏 doc-id 可读性并切断与 `--doc-id` 的复用点），也不自造 `%23` 链路（org 自身会对 `%` 二次转义，双重转义无法自洽）。

**复用点**：批注的 `location` 字符串**直接**作为链接片段，二者同源同构，不新增解析器。

**转义不变量**：`document_id`（含 `local:` 降级值）**不得包含 `#` 与 `%`**。生成链接时若检测到 doc-id 含这两个字符，`user-error` 明确报错并建议重命名文件（罕见路径，不引入转义链路）；`--parse-link` 因此只需「最后一个 `#` 分割」，行为可完全断言。

**默认摘录模板**（`seshat-reader-reference-format`，含 `%s` 占位符 `text`/`link`/`description` 三处）：

```
#+begin_quote
%s
#+end_quote
来源：[[%s][%s]]
```

### `:follow` 行为（关键细节）

1. `--parse-link` → doc-id；`--file-from-doc-id` → 绝对路径；
2. 路径为空或文件不存在 → `user-error`，提示检查 `seshat-reader-annotation-roots` 与书库路径；
3. **优先复用已有 buffer**：用 `(find-buffer-visiting file)`（内建，做路径规范化）——**不用 `get-file-buffer`**，它是 `buffer-file-name` 的精确字符串匹配，而 `--doc-id` 用 `file-truename` 归一化、`seshat-reader-open-doc` 存的是原始入参，两者形式不一致会让复用静默失效；命中且 `major-mode` 为 `seshat-reader-mode` 时 `pop-to-buffer`，否则 `(seshat-reader-open-doc file)`。**理由**：`seshat-reader-open-doc` 内部用 `create-file-buffer`，重复调用会产生 `file.pdf<2>` 之类的重复 buffer；
4. location 含 `page:<n>` → `(seshat-reader-goto-page n)`（1-based，直接传）；
5. location 含 `rect:` 时**不做任何 UI 动作**（无高亮能力），仅验证格式合法。

### 写入策略（`--insert-into-file`）

| 目标文件状态 | 行为 |
|---|---|
| 无关联 buffer | `append-to-file`（不打开 buffer，不干扰用户） |
| 有关联 buffer 且未修改 | 就地插入到末尾并保存 |
| 有关联 buffer 且已修改 | 插入并 `message` 提示「目标文件有未保存修改，请在插入后自行保存」 |

插入位置统一为**文件末尾**（不做「查找 `* 摘录` headline」的复杂逻辑，记入 tech-debt）。写入前校验文件存在于 `~/Org` 或 `~/seshat` 之外的路径时给出确认提示？——**不做**（过度防御），仅在 docstring 说明用途。

### 与 M7（uid 化）的关系

本步链接以 **doc-id 文本**承载身份。M7 引入 uid 后，只需替换两处：`seshat-reader-annotation--doc-id`（正向）与 `seshat-reader-reference--file-from-doc-id`（反向）；链接解析层可加 uid 形式回退分支。此迁移点在 `decisions.md` 记录。

## 注意事项

- **不改 vendored 文件**：`seshat-reader.el`/`-bookmark.el`/`-outline.el`/`-saveplace.el`/`render/` 一律不动；新逻辑只放 `seshat-reader-reference.el`（自研扩展），对 `annotation.el` 仅做 +3 行的文本属性新增
- **命名不变量**：新文件与全部公开符号前缀 `seshat-reader-reference-`；内部辅助用 `--`
- **不写用户文件到测试**：ERT 一律用临时文件；`seshat-reader-reference-target-file` 在测试中 `let` 绑定
- **不重复创建 buffer**：`:follow` 必须先用 `find-buffer-visiting` 查已有 buffer 且其 `major-mode` 为 `seshat-reader-mode` 再决定是否调用 `seshat-reader-open-doc`
- **链接解析用最后一个 `#` + 禁用转义**：`document_id` **不得含 `#`/`%`**（生成端 `user-error` 提示重命名），解析端因此只需「最后一个 `#` 分割」（`string-match "#\\([^#]*\\)\\'"`）；**禁止** `url-hexify-string`（会转义 `:`、`/`）与自造 `%23` 链路（org 会对 `%` 二次转义，双重转义不自洽）
- **buffer 复用用 `find-buffer-visiting`**：不用 `get-file-buffer`（精确字符串匹配，与 `file-truename` 归一化路径不一致会静默失效）
- **1-based 页码不变量**：`page:` 一律 1-based；若从 `seshat-reader-select-last` 的 `:page` 取值，该值已是 1-based（`annotation.el:210-230` 的既有语义），**不得再 `1+`**
- **org 为软依赖**：`(require 'org nil t)`；org 未加载时交互命令给可操作 `user-error`，不得 void-function 崩溃
- **服务端零改动**：本步不新增/修改任何 Go 文件；不新增服务端端点
- **密钥保护**：报告中不得出现任何令牌值；`seshat-rest-token` 仅从环境变量读取（沿用既有约定）
- **安全点**：T1 的 tar 即回滚点；验证失败按 L1→3 轮、L2/L3→2 轮的修复循环上限，耗尽则回滚并报告
- **范围纪律**：不做高亮、不做 EPUB location、不做服务端 refs、不做 `:complete`、不做反向索引、不做 Android —— 越界即停并报告
