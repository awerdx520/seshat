## 背景

M11.2a 已把 emacs-reader vendor 进本仓库并验证「整页文本 / 矩形取文」可用，但那是**编程式**调用（需手工输入页面坐标）。用户真正要的是**在阅读时长按鼠标框选一段文字**，进而（M12）做翻译 / LLM 解释 / OCR。

本期（M11.2b）实现「鼠标选区 → 取到选中文本」这条链路，**不含视觉高亮与批注持久化**（高亮需改 C 层渲染管线，另立 M11.2c）。

## 目标

在 `reader-mode` 中用鼠标拖拽框选一段文字，即时得到其文本（显示于 echo area，可选写入 kill-ring），且不破坏既有翻页、滚动、缩放等交互。

## 设计

### 现状约束（Phase 1 探索结论）

1. **显示机制**：每 window 一个 overlay，`display` 属性 = 页面 pixmap 图像；Emacs 中多个 overlay 的 `display` **不可叠加**（只有最高优先级生效）⇒ 本期不做视觉高亮。
2. **鼠标被禁用**：`reader-mode-map` 把 `<remap> <mouse-set-point>`、`<remap> <mouse-set-region>`、`<remap> <mouse-set-mark>`、`<remap> <mouse-set-secondary>`、`<remap> <mouse-drag-region>`、`<remap> <mouse-drag-secondary>` 全部 remap 为 `ignore`（原注释：避免 point 移动导致 cursor 画到页面外）。注意：这些是**命令 remap**，不作用于 `down-mouse-1` 之类的事件绑定；本期**不得移除**它们。
3. **取文本能力已具备**：`reader-dyn--text-in-rect(page x0 y0 x1 y1)`（页面坐标、0-based 页号、浮点参数）。

### 坐标换算（本期核心）

**屏幕坐标来源**：用 Emacs 原语 `(posn-object-x-y position)` 取**相对图像左上角**的像素坐标。该原语已排除 `window-vscroll` / `window-hscroll` / 居中（`reader--center-page`）造成的图像位移，**不需要**手动扣除偏移（`reader--get-prefix-width`、`reader--set-window-vscroll` 等是「把图像摆正」的工具，不参与坐标换算）。

**换算公式**（`rotate = 0`，页面 bbox 原点为 0）：

```
页面坐标 = 图像对象像素 × frame_scale / scale
```

- `scale`：窗口参数，取 `(reader-current-doc-scale-value window)`；
- `frame_scale`：窗口所在 frame 的缩放因子；
- 依据（`render/render-core.c`）：`ctm = fz_transform_page(bbox, resolution, rotate)`，其中 `resolution = scale × 72`；pixmap 物理像素 = 页面坐标 × scale；`imgw = pixmap_width / frame_scale`（物理 → 逻辑）。

**待验证假设（假设?）**：`posn-object-x-y` 返回的是**逻辑像素**还是**物理像素**，决定是否需要乘 `frame_scale` —— 列为本期 T6 的**首要验证项**。

**已知限制**：`rotate ≠ 0` 时结果为**静默错误**（rotate 只存在于 C 侧 `EmacsWinState`，elisp 侧无读取途径，**无法检测**）。本期只支持 `rotate = 0`。

### 其他实现要点

- **新增文件**：`emacs/seshat-reader/seshat-reader-select.el`（自研扩展；**不修改 vendored reader.el**，仅通过键绑定/hook 挂载）。
- **拖拽捕获**：使用 `mouse-drag-track`（其 `do-mouse-drag-region-post-process` 钩子），**不调用** `mouse-set-point` / `push-mark`，只记录起止 `posn` —— 从而不移动 point（规避 cursor 越界）。
- **换算函数入参**：签名须含 `window` 参数（每 window 有独立 overlay / `page` / `scale`），window 由 `(posn-window position)` 或事件解析得到，据此取 `reader-current-doc-scale-value` / `reader-current-doc-pagenumber` / 当前 overlay。
- **取文本**：调用 `reader-dyn--text-in-rect`。
- **反馈**：`message` 显示（超长截断）；可选 `kill-new` 写入 kill-ring。

## 结论

**判定：可行 ✅**（2026-10-12，用独立 GUI Emacs 实例 + `posn-at-x-y` 合成 posn 验证，未干扰运行中的 Emacs）

### 换算验证

- 环境：Emacs 31.1（pgtk / Wayland / WSLg）；`frame-scale-factor = 1.0`
- 样本：`/home/thomas/WorkSpace/notes/d2l-zh-pytorch.pdf` 第 1 页 —— **页面为 612×792pt（US Letter）**
- 图像几何：`:width/height = 519×671`（逻辑像素）；图像在窗口中的像素框 x∈[194,712]、y∈[0,670]
- **换算结果**：图像左上角 → `page(0.0, 0.0)`；右下角 → `page(611.4, 790.8)`（页面 612×792pt）⇒ **误差 < 1px（量化）**
- 交叉验证：由换算坐标取到的文本与手工页面坐标一致（同属作者行 y≈395，x 越大越靠右），文本顺序自洽

### 像素单位结论

- 判定 **`posn-object-x-y` 返回逻辑像素** ⇒ 公式 `page = 像素 × frame_scale / scale` **正确，无需修正**
- 依据：C 侧已做 device→logical 转换（`local_imgw = fz_pixmap_width / frame_scale` 作为 image 的 `:width`）；实测 `posn-object-x-y` 的取值范围与 `:width` 同尺度（C 侧与 elisp 侧均用 `frame-scale-factor`，量纲一致）
- ⚠️ **本机 `frame-scale-factor` 锁定 1.0（逻辑=物理），无法实证证伪** ⇒ 需在真 HiDPI 环境复验

### 已知限制（已写入模块 Commentary）

- `rotate ≠ 0` 为**静默错误**（rotate 只存在于 C 侧 `EmacsWinState`，elisp 侧不可读）
- 无视觉高亮（Emacs 多 overlay 的 `display` 不可叠加 → 需 C 层渲染，见 M11.2c）
- 扫描件（无文本层）取不到文本
- 多 frame 且缩放不一致时：本模块取 window 所在 frame 的 `frame-scale-factor`，而 C 侧在打开文档时按 selected frame 采样一次，两者可能不一致
- C 侧 `(int)` 截断带来 ~1px 量化误差

### 代码审查发现并已修复的问题

- **blocking**：拖拽命令缺 `select-window` ⇒ 在**非选中窗口**（分屏场景）拖选会静默失败（C 侧经 `selected-window` 解析文档）。已加 `(select-window window 'norecord)`。
- **major**：释放事件覆盖最后一次窗口内有效位置 ⇒ 已改为仅当释放位置仍在本窗口时更新。
- **important**：真正的拖拽释放事件是 `drag-mouse-1`，此前未被显式处理、靠 `reader-mode-map` 的 remap 兜底 ⇒ 已显式纳入。
