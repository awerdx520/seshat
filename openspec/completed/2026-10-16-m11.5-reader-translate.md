## 背景

阅读时需要就地翻译/解释鼠标选中的文本。已实测的现状：

- **gt.el v3.2.1** 已装并由用户在 `init-tools.el` 配置（word/sentence/paragraph 预设、`gt-htt-proxy`、youdao-dict + google 引擎、`gt-posframe-pop-render` 弹窗）
- **`gt-taker` 的 `:text` 类型为 `(or function symbol string)`** —— 阅读器选区文本（字符串）可直接作为翻译源，无需 hack
- **`gt-chatgpt-engine`** 提供 `host`/`path`/`model`/`key`/`prompt`/`temperature` 等参数（可指向任意 OpenAI 兼容端点）
- **posframe v1.5.2** 已装、Emacs 31.1 child-frame 正常；项目内已有 6 处 posframe 用法可参考
- 服务端 LLM 增值层尚未暴露客户端 HTTP 接口（`internal/api/server.go` 零命中）→ 本步**不依赖服务端**

> 方案沿革（2026-10-16）：本里程碑最初设计为「自建 Elisp + gptel + 专用 org buffer」，经用户裁决改为「复用 go-translate（gt）+ posframe 弹窗，并新建 gt 预设供阅读器使用」；旧版计划文件已废弃移除。

## 目标

1. 在阅读器内对鼠标选区一键**翻译**，结果用 posframe 弹出；
2. 对选区一键 **LLM 解释**（走 `gt-chatgpt-engine`），结果同样 posframe；
3. 支持「**新建 gt 配置供阅读器使用**」：在 thomas-emacs 侧追加 gt 预设（`reader`/`reader-explain`），包内按预设名取用、缺失时回退内置默认；
4. 结果可一键**存为批注**（复用 M11.3 链路）；
5. 对 gt 保持**软依赖**（未加载时命令给可操作错误，不影响阅读器其它功能）。

### 实现要点

- **取文本**：`(plist-get seshat-reader-select-last :text)`；为空 → `user-error`（提示「选区无文本；扫描件需 OCR（M11.6）」）
- **`:pick nil` 必须显式设置（易错点）**：`gt-taker` 的 `pick` slot 无默认值，会回退到变量 `gt-taker-pick`（默认 `'paragraph`）→ 会把选区文本**按段落切分**，甚至抛 `Nothing picked, empty request`。所有 taker（包内与 thomas-emacs 侧预设）一律显式 `:pick nil`。
- **注入方式（不得 oset 共享单例）**：`gt-preset-translators` 中的 translator 与其 taker 是 `gt-single` 按 slots 哈希缓存的**全局共享对象**；直接 `(oset taker :text TEXT)` 会永久改写预设、并在不同选区之间互相覆盖。统一路径：
  1. 取预设：`(alist-get PRESET (gt-ensure-plain gt-preset-translators))`（`gt-ensure-plain` 对非函数值**原样透传**）；不存在 → 构造回退 translator（`gt-youdao-dict-engine` + `gt-google-engine` + `gt-posframe-pop-render`）并 `message` 提示；
  2. `(clone PRESET-TRANS)` 后**重建 taker**：`(oset trans taker (gt-taker :text TEXT :pick nil :langs LANGS))`（`clone` 是浅拷贝，taker slot 仍指向共享对象，**必须重建**）；
  3. 渲染方式：`seshat-reader-translate-render` 为 `pin` 时 `(oset trans render (gt-posframe-pin-render))`，否则沿用预设/回退的 pop 渲染。
- **启动**：直接 `(gt-start TRANSLATOR)`（`gt-start` → `gt-init` 内部已 reset 并清空 text/target）；**不要**为复用语义而绑定 `gt-default-translator`（会带来改变全局默认翻译器的副作用风险）。
- **译文捕获（供存批注使用）**：**不读 posframe 缓冲区**——pop 与 pin 是**两个不同缓冲区**（`gt-posframe-pop-render-buffer` / `gt-posframe-pin-render-buffer`），且 pin 缓冲含 header 与原文。改为在 render 的输出 hook 中按 `gt-result` 文本属性提取纯译文，存全局变量：
  - `(defvar seshat-reader-translate-last-result nil "最近一次翻译/解释的纯译文；供存为批注使用。")`
  - 捕获函数：用 `text-property-search-forward 'gt-result` 收集片段后 `string-join`（去 properties）；
  - **pop 与 pin 两个 output hook 都要挂**该函数（`gt-posframe-pop-render-output-hook`、`gt-posframe-pin-render-output-hook`）；
  - pop 渲染的 30s 超时只删 frame、**不 kill buffer**，因此该路径对 pop 同样可靠。
- **失败反馈**：`gt-start` 在无法创建任务时抛 `user-error`（语言对不足、引擎校验失败等）；异步翻译失败由 render 以错误 face 写入缓冲区，捕获 hook 检测失败状态时须 `message` 明确提示。命令自身**不得让异常冒泡成 backtrace**。

### 明确不在本步（范围外）

服务端 LLM HTTP 端点与本地节点路由、**OCR（属 M11.6）**、多轮对话界面、译文写回文档、页面内高亮渲染、批量翻译整本。

## 注意事项

- **gt 为软依赖**：包内不得 `(require 'gt)`（硬依赖），一律 `(require 'gt nil t)` + 运行期检查
- **不改既有 gt 配置**：只**追加**预设，禁止覆盖 `gt-preset-translators` 中既有项或用户既有 `gt-*` 变量
- **密钥保护**：`gt-chatgpt-engine` 的 key 一律走 authinfo/环境变量，禁止写入任何仓库文件；报告中不得出现任何密钥值
