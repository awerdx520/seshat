## 背景

**产品要求（用户 2026-10-16）**：批注在服务不可用时应**使用本地缓存、不报"服务不可用"**，等服务能连接时再**自动同步**。

现状（M11.3 实现）与之冲突：`seshat-reader-annotation-create` 在请求异常或非 2xx 时只 `message` 报失败并**丢弃批注**；`-list` 在 `--fetch` 拿到哨兵时不渲染（用户什么都看不到）。阅读场景（移动/断网/服务未启动）本应「先记录、后同步」，网络状态不应决定用户能否做批注。

**M11.5 收尾**：诊断（独立实例实测）确认 LLM 解释链路本身正确（DeepSeek 端点 HTTP 200、key 有效、posframe 在 GUI 正常），但存在 3 个缺陷：① `reader-explain` 预设未覆盖 gt 的默认**翻译** prompt，导致「解释」实际输出译文；② `gt-posframe-pop-render-timeout`（30s）小于引擎 `:timeout`（60s），慢响应时弹窗先消失且 gt 失败**完全静默**；③ 用户配置里的 `gt-htt-proxy` 拼写有误（gt 实际读取 `gt-http-proxy`）。

## 目标

1. 批注创建/删除在服务不可用时**入本地队列**，用户得到的是「已存入本地，待联网同步」而非错误；
2. 批注列表**合并**服务端结果与本地待同步项（本地项标记 `[待同步]`），离线时也能看到刚做的批注；
3. 服务恢复后**自动同步**（启动后、定时、手动、list 前机会性），同步成功后队列项移除；
4. 同步具备**幂等/去重**能力，避免重试造成重复批注；
5. 收尾修复 M11.5 的 3 项缺陷。

### 队列文件与条目结构

- 文件：`seshat-reader-annotation-queue-file`（defcustom，默认 `~/.local/share/seshat/annotation-queue.eld`）
- 写入：`prin1` 整个队列到临时文件后 `rename-file`（原子替换，避免半写损坏）
- 条目（plist 列表）：
  - create：`(:uuid "…" :action create :document-id "ebook:x.pdf" :location "page:3;rect:…" :text "…" :queued-at "ISO8601")`
  - delete：`(:uuid "…" :action delete :id 7 :queued-at "ISO8601")`
- `:uuid` 由 `(format-time-string "%Y%m%dT%H%M%S" nil t)` + 随机后缀生成，用于精确定位与移除
- 上限：`seshat-reader-annotation-queue-max-entries`（defcustom，默认 `1000`）——队列达到上限时**拒绝入队**并 `message` 提示，避免无限增长（无自动清理策略，记入 tech-debt）

### UUID 语义（离线删除的关键）

- 离线创建的批注**尚无服务端 id**；列表渲染本地项时在**文本属性**中携带队列项 `:uuid`（新增属性 `seshat-reader-annotation-queue-uuid`，服务端项为 nil）。
- 删除路径（`seshat-reader-annotation-list-delete`，即列表 buffer 中的 `d`）：
  - 该行**有** `seshat-reader-annotation-queue-uuid` → 直接调 `seshat-reader-annotation-queue-remove UUID`（即「取消本地待同步批注」，**不发任何 HTTP**）；
  - 该行**无** uuid（服务端项）→ 走既有 `seshat-reader-annotation-delete ID`（失败则入 delete 队列）。
- **不做** `(document-id, location, text)` 反查（同位置同文本可能有多条，反查有歧义），因此**不提供** `-find-pending-create`。
- `seshat-reader-annotation-delete (id)` 保持原语义（只接收服务端 id）。

### 三个接入点改造

| 接入点 | 新行为 |
|---|---|
| `seshat-reader-annotation-create` | REST 成功 → 照旧 `message` 报 id；**异常或非 2xx** → 入队并 `message`「批注已存入本地待同步队列（N 条待同步）」（**任何「服务/服务端不可用」类字样一律不得出现**——用户明确要求离线时不报服务不可用） |
| `seshat-reader-annotation-delete` | **保持原语义**（只接收服务端 id；REST 失败则入 delete 队列）；**uuid 分支不在本函数**，由列表中的 `seshat-reader-annotation-list-delete` 承担（见「UUID 语义」节） |
| `seshat-reader-annotation-list` | 拉取成功 → 渲染服务端结果 + 本地队列项（标 `[待同步]`）；拉取失败 → **仍渲染本地队列项**（标 `[待同步]`）并柔和提示「（离线）仅显示本地待同步批注 N 条」；列表的 `RET`/`d` 对本地项同样可用 |

### 自动同步

- 手动：`seshat-reader-annotation-queue-sync (&optional document-id)`——逐条处理；**每处理完一条即重新读取队列、按 uuid 移除该条并原子写回**（避免与用户并发入队的竞态）；任一项因服务不可用失败即**停止**（保留剩余队列，不报错，`message` 一行汇总「已同步 N 条，剩余 M 条」）；返回 `(成功数 . 剩余数)`
- 自动：
  - defcustom `seshat-reader-annotation-queue-auto-sync`（默认 `t`）、`seshat-reader-annotation-queue-sync-interval`（默认 `300` 秒）
  - 启动后延迟首次 + 周期同步：**统一用 `run-with-timer`**（`run-with-idle-timer` 在 `emacs --daemon` 下无 idle 概念、不可靠）
  - `-enable-timer` / `-disable-timer` 幂等（重复 enable 不叠加多个定时器）
  - **机会性同步**：① `-list` 拉取服务端**成功**后顺便 sync（离线时不触发，避免额外等待）；② `-create` REST **成功**且队列非空时也顺便 sync（此时服务端显然可用）
- 列表排序：服务端项按既有（id 升序）在前，本地 `[待同步]` 项**追加在后**（实现简单、语义清晰）

### 去重（防重复批注）

- create 同步前先经 **`seshat-reader-annotation--fetch (document-id)`** 拉取该文档批注（该函数能区分「空列表」与「拉取失败哨兵」，优于 `seshat-rest-list-annotations`）：
  - 返回 `seshat-reader-annotation--fetch-error` 哨兵 → 视为**服务不可用**，停止同步、保留队列；
  - 返回列表（含空列表）→ 比对 `(alist-get 'location item)` 与 `(alist-get 'text item)`（**键为 symbol**，因 `seshat-rest--json` 用 `:object-type 'alist`）是否与队列项完全相同：相同 → 视为已同步（移除队列项，**不发 POST**）；否则 POST。
- 该策略对「用户有意在同一位置提交相同文本两次」不敏感（视为同一条），记入 tech-debt；根治需服务端新增 `client_uuid` 字段（本步零服务端改动）。

### M11.5 收尾修复（T1）

1. `init-tools.el` 的 `reader-explain` 预设：给 `gt-chatgpt-engine` 显式覆盖解释语义——
   `:root "You are a helpful assistant that explains text concisely."`
   `:prompt "请用中文简要解释下面的文本（讲清含义与用法），不要逐字翻译：\n\n{{text}}"`
   （gt 的 `prompt` 为字符串时按 `{{lang}}`/`{{text}}` 占位符替换，缺失占位符安全跳过。**注意**：若改用函数，其签名为 `(item tgt)`，其中 `tgt` 是**语言符号**（如 `zh`）而非字符串，直接 `format` 会得到「请用zh…」——因此以字符串模板为准。）
2. `init-tools.el`：`(setq gt-posframe-pop-render-timeout 90)`——该变量是 **posframe 展示时长**（默认 30s 后自动隐藏），与引擎 `:timeout`（HTTP 请求超时 60s）属**不同层面**；展示时长过短会导致「请求耗时超过展示时长时弹窗先消失、结果不可见」。副作用：快速响应时弹窗也会停留 90s（可接受，嫌久可改小）。
   同时**修正拼写**：`gt-htt-proxy` → `gt-http-proxy`（gt 实际读取后者）。注意：修正后请求将**经代理**（此前是直连），需在 T9 验证各端点经代理仍可用。
3. 失败可见性：**不新增代码**——由第 2 项（调大展示时长）+ `seshat-reader-translate--capture-result` **既有的失败 `message`**（检测到 error face 或无 `gt-result` 片段时提示）承担；本项改为 **T9 真机验证**（断网/超时场景下失败提示是否可见）。若实测发现 hook 未触发导致仍静默，再单独补兜底方案并在报告中记录实测结论。

  **场景丙（代理与失败可见性）**：确认**断网/超时场景下 LLM 翻译/解释的失败提示可见**（M11.5 收尾修复第 3 项的承载点），以及**翻译/解释经代理可用**（`gt-http-proxy` 修正后请求将走代理，需确认 youdao / google / DeepSeek 端点均可达）。
  最后确认 evil 环境下列表键位正常。

## 注意事项

- **绝不写用户真实队列文件到测试**：ERT 必须用临时文件；`seshat-reader-annotation-queue-file` 在测试中一律 `let` 绑定
- **离线时不得出现「服务不可用」类报错**（用户明确要求）：失败路径的措辞统一为「已存入本地待同步队列」/「（离线）仅显示本地待同步批注」；只有**同步**过程中才可有汇总提示
- **原子写队列**：先写临时文件再 `rename-file`；文件损坏时保留原文件并报错，不得静默覆盖
- **UUID 语义**：离线创建的批注被删除时应**取消队列中的 create**，而非生成无 id 的 delete
- **幂等去重**：create 同步前必须比对服务端现有 `(location, text)`，避免重试产生重复批注
- **定时器幂等**：`-enable-timer` 重复调用不得叠加多个定时器
- **不改服务端**：本步零 Go 改动；不引入 client_uuid（记 tech-debt）
- **密钥保护**：报告中不得出现任何密钥值；`gt-http-proxy` 修正只改变量名，不改代理地址
- **命名不变量**：新文件与公开符号一律 `seshat-reader-annotation-queue-*`
- **范围纪律**：不做进度离线、不做高亮可视化、不做冲突解决、不做 Android/Web 侧 —— 越界即停并报告
- **离线删除只走 uuid**：列表本地项携带 `seshat-reader-annotation-queue-uuid` 文本属性，`d` 按 uuid 移除；**禁止**按 `(document-id, location, text)` 反查（同位置同文本会有歧义）
- **队列上限**：`-max-entries`（默认 1000）达上限时拒绝入队并提示；无自动清理策略（记 tech-debt）
- **定时同步用 `run-with-timer`**：`run-with-idle-timer` 在 `emacs --daemon` 下不可靠，启动后延迟首次与周期同步一律用 `run-with-timer`
