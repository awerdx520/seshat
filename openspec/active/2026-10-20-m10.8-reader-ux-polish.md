### 0. 共同约束
- **依赖例外（用户 2026-10-20 明确授权）**：引入 `com.tom-roush:pdfbox-android`（约 +10 MB）用于读 PDF outline。仅此一处新增依赖，其余仍零新增。

- 阅读区与浮层：浮层必须是 **FrameLayout 内的 overlay**（`layout_gravity`），阅读区 `match_parent` + `clipToPadding=false`，padding 由代码按浮层**可见高度**动态设置。

### A1 浮层 overlay 与 padding 联动（U1）
- `toggleChrome()` 改为：
  ```kotlin
  private fun toggleChrome() {
      val show = topChrome.visibility != View.VISIBLE
      val vis = if (show) View.VISIBLE else View.GONE
      topChrome.visibility = vis; bottomChrome.visibility = vis
      applyContentPadding()          // 关键：按当前可见性重设 padding
  }
  private fun applyContentPadding() {
      val top = if (topChrome.visibility == View.VISIBLE) topChrome.height else 0
      val bottom = if (bottomChrome.visibility == View.VISIBLE) bottomChrome.height else 0
      readContainer().forEach { it.setPadding(0, top, 0, bottom) }   // pager 内部 RecyclerView + scrollView
  }
  ```
- **浮层高度变化时（字体缩放/旋转/insets）也要重算**：保留现有 `addOnLayoutChangeListener`，但改为「高度变化即 `applyContentPadding()`」（不再一次性置位）。
- 验收：浮层隐藏后底部无留白；显示后末行不被遮挡。
- **PDF 侧同样适用**（`PdfReaderActivity`）：现有 `toggleChrome()` 只改 `chrome.visibility`，
  注释已自述「隐藏浮层底部留白」。改为调用同一套 `applyContentPadding()`：
  `recycler.setPadding(0, 0, 0, if (chrome.visibility == VISIBLE) chrome.height else 0)` + `clipToPadding=false`。
  **A-T1 必须同时改 EPUB 与 PDF 两个 Activity**，不得只做 EPUB。
- **必须同步重算章内偏移**（否则破坏 M10.6 的进度不变量）：
  `reportVisibleChapter()` 的 `scrollY = paddingTop - centerView.top` 与
  `viewportCenter = paddingTop + (height - paddingTop - paddingBottom)/2` 都**实时读 padding**；
  但 `toggleChrome()` 改 padding 只触发**重新布局**，`onScrolled` 在 `dy == 0` 时**不回调**，
  故 `visibleChapterScrollY` / `scrollByChapter` 不会自动重算 → 持久化的章内偏移随 padding 漂移。
  修法：`applyContentPadding()` 末尾调用一次 `reportVisibleChapter()`（复用既有链路，不新写状态）。
  验收：连续显隐工具栏 3 次后，`ReadingProgress.scrollY` 的语义仍指向同一视觉位置（误差 ≤ 1 行高）。

### A2 竖向模式 tap 分区（U2）
- `onSingleTapUp(e)` 按**可见宽度**分区，行为按「模式 × 区域」四分支：

| 模式 | PREV 区（x < 25%） | NEXT 区（x > 75%） | 中间 |
|---|---|---|---|
| EPUB 竖向 | `scrollView.smoothScrollBy(0, -viewportHeight)` | `smoothScrollBy(0, +viewportHeight)` | toggleChrome |
| EPUB 横向 | 复用既有 `moveBy(-1)` | `moveBy(+1)` | toggleChrome |
| PDF 竖向 | `recycler.smoothScrollBy(0, -viewportHeight)` | `smoothScrollBy(0, +viewportHeight)` | toggleChrome |
| PDF 横向 | 复用既有 `movePage(-1)` | `movePage(+1)` | toggleChrome |

- **不要新写翻页逻辑**：横向一律复用 `EpubReaderActivity.moveBy` / `PdfReaderActivity.movePage`（它们已处理边界与吸附）。
- 统一用 `smoothScrollBy`（计划此前 `scrollBy` 与 `smoothScrollBy` 混用，以本表为准）。
- 把分区判定抽成纯函数便于测试：
  ```kotlin
  internal object TapZone {
      enum class Zone { PREV, NEXT, TOGGLE }
      /** fraction ∈ [0,1]；leftEdge/rightEdge 为边缘比例（如 0.25/0.75）。 */
      fun zone(fraction: Float, leftEdge: Float = 0.25f, rightEdge: Float = 0.75f): Zone
  }
  ```
  测试 ≥5 例（边界 0.25/0.75、越界、负值）。

### A4 目录（U4）
**EPUB（复用）**：`showToc()` 已存在（`book.chapters` + 当前章高亮），只把入口从底栏移到 `topBar.tocButton`。

**PDF（新增，PdfBox-Android）**：
- 依赖：`implementation("com.tom-roush:pdfbox-android:2.0.27.0")`（若 Maven Central 有更新 2.x 用最新）
- 初始化：`PDFBoxResourceLoader.init(applicationContext)` 在 `PdfReaderActivity.onCreate` 首次调用（只调一次）
- 新增 `reader/PdfOutlineReader.kt`：
  ```kotlin
  data class PdfOutlineItem(val title: String, val pageIndex: Int, val children: List<PdfOutlineItem>)

  internal object PdfOutlineReader {
      /** 读 PDF outline；无 outline / 解析失败 → 返回空表（不抛）。 */
      fun read(file: File): List<PdfOutlineItem>
      /** 拍平成「缩进标题 + 页码」列表（供对话框展示）。 */
      fun flatten(items: List<PdfOutlineItem>, depth: Int = 0): List<FlatOutlineItem>
  }
  data class FlatOutlineItem(val title: String, val pageIndex: Int, val depth: Int)
  ```
  实现要点：`PDDocument.load(file)` → `document.documentCatalog.outline` → 递归 `PDOutlineItem`（`title` / `destination` → `PDDocumentOutline` 的 `page` 索引）；`document.close()` 必须在 `finally`。
- page index 用 `(destination as? PDPageDestination)?.retrievePageNumber()`；
  该方法内部遍历页面（**O(n)**），大文档应在一次遍历中缓存 `PDPage → index` 映射后复用。
- **线程与内存约束（硬性）**：
  - `PdfOutlineReader.read()` 是阻塞 + 高内存操作，**调用方必须放在后台 executor**（`PdfReaderActivity` 现有的单线程渲染 executor 或新建 IO executor）；
  - **大文件阈值**：`file.length() > 50 MiB` 时**直接跳过 outline 解析**，改用「页码目录」回退（避免 96 MB 级 PDF OOM）；
  - `PDDocument.load(file)` 后必须 `try/finally` 关闭；`InvalidPasswordException`（加密）与 `IOException` 都 → 返回空表 + 回退。
- 目录对话框（`showPdfToc()`）：`AlertDialog` + `setSingleChoiceItems(标题列表, 当前页对应项)` → 点击 `recycler.scrollToPosition(pageIndex)`。
- **回退**：`read()` 返回空 → 用「页码目录」（每页一行「第 N 页」）或直接提示「本书无目录」。
- 加密/损坏 PDF → `read()` 返回空 + Toast，不崩溃。

### 对计划的偏离（实施中发现，已采纳）

1. **EPUB「批注」按钮没删，移到顶栏**：它是 `addAnnotationFromSelection()` 的唯一入口，直接删会让批注能力消失。
2. **PDF 单击延迟改用 `ViewConfiguration.getDoubleTapTimeout()`**（计划写 250ms）：250ms 短于系统 300ms 双击窗口，慢双击会「先翻一页再进手写」。
3. **手写面板拆成三行**（颜色行 / 粗细行 / 笔型行）：原设计 6 个 chip 一行约 381dp，360dp 屏会裁掉最右一个。
4. **PDF outline 包名**：pdfbox-android 把 `org.apache.pdfbox` 重定位为 `com.tom_roush.pdfbox`，计划里的静态检查规则相应改用后者。
5. **`PdfOutlineReaderTest` 走真解析而非纯函数回退**：pdfbox 的 `PDDocument.load` 在纯 JVM 可运行（只需不 import 到 test 源集），故 12 例真解析用例全部生效。

## 注意事项
- **PdfBox-Android 是显式破例**（用户 2026-10-20 授权）：只在 PDF 目录用，不得扩散到其它模块；`PDFBoxResourceLoader.init` 只调一次
- **浮层 padding 必须与可见性联动**：这是 U1 的核心，不要退回「只设一次」
- **tap 分区不要吞掉滚动**：`OnItemTouchListener.onInterceptTouchEvent` 仍恒返回 false
- **手写归一化坐标不得改**（M10.5 不变量）；新增字段只加不改
- **不做**：阅读设置面板（只跳设置页）、手写笔型跨文档记忆、PDF 目录编辑
