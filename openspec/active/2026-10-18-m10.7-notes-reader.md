# M10.7 笔记阅读器（多文件笔记库 + org/markdown 渲染）

## 当前状态
- 阶段：Phase 2（Plan）· 计划已写入，待独立审查
- 已确认：方案 ✅（用户 2026-10-18 确认：私有目录 + 可选 SAF 外部目录、WebView 渲染、保留 Agenda 与源码编辑）
- 下一步：独立审查 → 用户确认计划 → Phase 3 实施
- 复杂度：大（约 12 文件 / 约 2000 行 / 新渲染层）
- 关联：M10.6 B4 已交付「单 org 文件 TODO 树」，本里程碑把它替换为「笔记库 + 渲染阅读」；B4 的 OrgTree/GtdSorter/NotesSync/NotesEditActivity 复用不删。B4 的 `NotesEditActivity` 保留用于「按条目编辑」，M10.7 新增文件级编辑器。

## 目标
1. **笔记库**：扫描两处来源的 `.org` / `.md` 文件——① App 私有 `filesDir/notes/`（默认）；② 用户可选的一个外部目录（SAF tree URI + 持久授权）。每个文件是一条笔记，不再把「一个文件的 headline 树」当列表。
2. **渲染阅读**：点击笔记进入渲染视图（WebView），支持 org 与 markdown 的主要语法，纯笔记（无 TODO）与 TODO 笔记同样可读。
3. **保留**：Agenda 分段（TODO 汇总）、源码编辑（`NotesEditActivity`）、`NotesSync` 上传。
4. **移除**：把单文件树当主列表的形态（层级树改为阅读页内的可选大纲，属后续增强，本计划不做）。

## 设计

### 0. 共同约束
- **零新增依赖**：不引 `androidx.documentfile`、不引 markdown 库。SAF 遍历用 framework 的 `DocumentsContract` + `ContentResolver.query`。
- 不破坏既有不变量：M9.1（令牌只经 `putSecret`）、M9.2 存储分层、M9.2 渲染管线、M10.5 手写、M10.6 服务端可选。
- 渲染器必须**纯 JVM 可测**（输入文本 → 输出 HTML 字符串），不得依赖 Android 类。

### 1. 数据层（`notes/` 包，新建）
```kotlin
enum class NoteFormat { ORG, MARKDOWN }

/** 统一引用：私有目录文件或 SAF 文档。 */
sealed interface NoteRef {
    data class LocalFile(val file: File) : NoteRef
    data class SafDocument(val uri: Uri) : NoteRef
}

data class NoteItem(
    val ref: NoteRef,
    val title: String,
    val format: NoteFormat,
    val modifiedAt: Long,
    val tags: List<String>,
    val source: NoteSourceKind,   // PRIVATE / EXTERNAL
)

enum class NoteSourceKind { PRIVATE, EXTERNAL }
```
- `NoteScanner`：
  - `scan(privateDir: File, externalTreeUri: Uri?, resolver: ContentResolver): List<NoteItem>` —— 但为了纯 JVM 可测，拆成两层：
    - `NoteScanner.scanLocal(dir: File): List<NoteItem>`（纯 JVM，测试用 TemporaryFolder）
    - `NoteScanner.scanSaf(resolver, treeUri): List<NoteItem>`（Android，无单测）
    - SAF 遍历实现指引（framework，不引依赖）：
      `DocumentsContract.buildChildDocumentsUriUsingTree(treeUri, DocumentsContract.getTreeDocumentId(treeUri))`
      → `resolver.query(childrenUri, arrayOf(Document.COLUMN_DOCUMENT_ID, Document.COLUMN_DISPLAY_NAME, Document.COLUMN_MIME_TYPE, Document.COLUMN_LAST_MODIFIED), null, null, null)`
      → 只取 `MIME_TYPE != DIRECTORY` 且扩展名命中；`NoteRef.SafDocument(Uri)` 用
      `DocumentsContract.buildDocumentUriUsingTree(treeUri, documentId)` 构造（**不要**用裸 `Uri.parse`）。
      只遍历一层（不递归子目录，记 tech-debt）。
  - 只取扩展名 `.org` / `.md`（忽略大小写）；忽略子目录（本计划不做递归）。
  - **denote 文件名解析**（纯函数，可测）：
    ```kotlin
    internal object DenoteName {
        /** `20240101T120000--标题__tag1_tag2.org` → (标题, [tag1, tag2])；不匹配返回 null。 */
        fun parse(fileName: String): ParsedName?
        data class ParsedName(val title: String, val tags: List<String>)
    }
    ```
    规则：正则 `^(\d{8}T\d{6})--(.+?)(?:__([A-Za-z0-9_@#%-]+))?\.(org|md)$`；标题中的 `_` 视为空格？——**不做**（保持原样，只把 `--` 后、`__` 前作为标题）；标签按 `_` 分割、过滤空串。
  - **标题回退链**：denote 解析成功 → 用它；否则读文件首个 heading（org：`^\*+\s+(?:TODO|DONE|NEXT|WAITING|CANCELLED)?\s*(?:\[#[A-Z]\]\s*)?(.+)$` 的首个匹配；md：首个 `^#\s+(.+)$`）；再否则用文件名去扩展名。
    > 注意：回退链需要读文件内容 → 属于 IO，放在扫描里做（大批量时慢，记 tech-debt）。
- `NoteReader`：`read(ref: NoteRef, resolver: ContentResolver?): String?`（LocalFile → `file.readText()`；SafDocument → `resolver.openInputStream`）。

### 2. 渲染层（`notes/render/`，新建，全部纯 JVM）
```kotlin
/** 统一 HTML 包装：内联 CSS（暗/亮自适应用 prefers-color-scheme）+ <article>。 */
internal object HtmlDocument {
    fun wrap(bodyHtml: String): String
}

internal object OrgHtmlRenderer {
    /**
     * 支持：标题 `*`~`*****` → h1..h5；TODO 关键字着色（TODO/NEXT/WAITING/DONE/CANCELLED）；
     * 行内 `*粗*` `/斜/` `_下_` `=等宽=` `~代码~` `+删除+`；无序列表 `-`/`+`、有序 `1.`；
     * `#+BEGIN_SRC lang ... #+END_SRC` → <pre><code>；`#+BEGIN_QUOTE`/`#+END_QUOTE` → blockquote；
     * 链接 `[[url][text]]`、`[[url]]`；
     * `:PROPERTIES:`..`:END:` 抽屉渲染为 `<details><summary>属性</summary>…</details>`（**默认折叠但可展开**，不隐藏——用户需要能看到自己的属性）；`#+TITLE:`/`#+FILETAGS:` 等关键字行隐藏。
     */
    fun render(text: String): String
}

internal object MarkdownHtmlRenderer {
    /**
     * 支持：ATX 标题 `#`~`######`；`**粗**` `*斜*` `` `代码` `` `~~删除~~`；无序 `-`/`*`/`+`、有序 `1.`；
     * 围栏代码块 ``` ```lang ```；行内链接 `[t](u)`；引用 `>`；水平线 `---`。
     */
    fun render(text: String): String
}
```
- **HTML 转义与解析顺序（硬约束）**：
  1. 先对**原始文本**做 HTML 转义（`& < > "`）；
  2. 再在**已转义文本**上匹配行内标记（`*粗*` `/斜/` `_下_` `=`等宽` `~代码~` `+删除+`），把标记替换为白名单标签；
  3. **代码块/行内代码的内容只转义、不解析行内标记**（避免二次解析）；
  4. 链接的 URL 必须校验 scheme 白名单（`http`/`https`/`mailto`），其余降级为纯文本；标题/属性位置不拼接用户文本。
  两个渲染器的公共实现放 `RenderSupport`，并各补「`*<script>*` 只转义不执行」「URL 非法 scheme 被降级」的测试。
- **表格本计划不做**：`|a|b|` 与 GFM 表格按普通段落文本输出（保留原字符），`<table>` 渲染留待后续（记 tech-debt）。理由：自研表格解析需处理对齐/列宽/转义/无分隔行容错，风险与收益不匹配。
- **不追求完整语法**：未识别语法按普通段落输出（宁可朴素，不可崩溃）。
- 两个渲染器的公共工具（转义、行内强调、列表累积）抽到 `notes/render/RenderSupport.kt`，避免两份重复。

### 3. UI 层
- `ui/NotesFragment`（改造）：
  - 列表数据源改为 `NoteItem`（**移除**按单文件构树的逻辑，但 `OrgTree` 等类保留不删）；
  - 行 UI：**新建** `res/layout/item_note_file.xml`（标题 + 修改时间 + 标签），由新建的 `NoteFileAdapter` 使用；**不复用** `item_note_entry.xml`（后者继续服务 Agenda 段的 `NotesListAdapter`）
  - 搜索：对**文件名标题 + 标签**匹配（不再搜正文，避免每次按键读所有文件；正文搜索记 tech-debt）；
  - 分段：「笔记 / Agenda」，默认**笔记**
    - **笔记段**：`List<NoteItem>`，adapter 为新建 `NoteFileAdapter`（行：标题 + 修改时间 + 标签）
    - **Agenda 段**：**汇总所有来源（私有 + 外部）中 `.org` 文件的 TODO 条目并集**（每个文件单独 parse 后合并），行模型沿用 `VisibleRow`（depth=0、hasChildren=false），adapter 沿用既有 `NotesListAdapter`
    - 分段切换时 **swap `notesList.adapter`**（两个 adapter 各自持有自己的数据），不要试图用一个 adapter 同时绑定两种行
    - `NotesListAdapter`（B4 产物）**保留**，仅服务 Agenda 段；`OrgTree`/`GtdSorter`/`OrgSearchMatcher` 保留
  - 点击笔记 → `NoteViewActivity`（渲染）；长按 → 菜单（在阅读页内提供「编辑源码」入口即可，长按菜单本计划不做）；
  - 顶部保留「刷新」「选择目录」入口（选择目录跳设置页）。
- `ui/NoteViewActivity`（新建）：
  - `intent(context, ref: NoteRef, title: String)`（`NoteRef` 用 `EXTRA_PATH` / `EXTRA_URI` 二选一传）；
  - WebView 加载 `HtmlDocument.wrap(renderer.render(text))`（`loadDataWithBaseURL(null, html, "text/html", "utf-8", null)`）；
  - 菜单「编辑源码」→ **新增 `NoteEditActivity`**（文件级：整文件文本 EditText + 保存），**不复用** entry 级的 `NotesEditActivity`；
  - 仅 `NoteRef.LocalFile` 显示该按钮；`NoteRef.SafDocument` **隐藏按钮**（SAF 只读，不做写入）；
  - 保存写回后 `finish()`，`NoteViewActivity` 重新加载并重渲染。
  - WebView 安全：`javaScriptEnabled = false`（渲染不需要 JS）、`allowFileAccess = false`、`allowContentAccess = false`、禁用 `file://` 访问、`setBackgroundColor` 跟随主题。
- `settings/SettingsActivity` 新增「笔记外部目录」：
  - 使用 `ActivityResultContracts.OpenDocumentTree` 选目录 → `contentResolver.takePersistableUriPermission(uri, FLAG_GRANT_READ_URI_PERMISSION)` → 存入 `AppPreferences`（新增键 `notes_external_dir`）；
  - 清除按钮：`releasePersistableUriPermission` + 清键。

## 注意事项
- **不改** B4 的 `OrgTree`/`GtdSorter`/`NotesSync`/`NotesEditActivity`（复用）；M10.7 的「编辑源码」走**新增的文件级** `NoteEditActivity`，不复用 entry 级编辑器（语义不同：整文件 vs 单条 headline）；`NotesFragment` 的 Agenda 段逻辑保留。
- 渲染器只输出 HTML 片段，**所有文本必须转义**；禁止把用户文本拼进属性或 `<script>`。
- `NoteViewActivity` 的 WebView 必须关 JS / 关 file access（渲染不需要，开启会引入 XSS 面）。
- SAF 授权必须 `takePersistableUriPermission`，否则重启后失效。
- 大目录（数千文件）扫描需在后台线程，列表显示加载态；不做增量/缓存（记 tech-debt）。
- 不实现：富文本编辑、图片内联渲染（`[[file:...]]` 只显示为链接文本）、大纲侧栏、阅读位置记忆（均记 tech-debt）。
