# M10.9 目录抽屉：树形层级 + 左侧滑出

## 当前状态
- 阶段：Phase 2（Plan）· 计划待独立审查
- 已确认：方案 ✅（用户 2026-10-20 确认「含 EPUB 解析层改造 + 可折叠」）
- 前置：M10.8（阅读器 UX 重排）代码已完成并提交，U1 padding 修复（`bb759f1`）待真机复验
- 复杂度：中（约 10 文件 / 约 900 行 / 无新增依赖）
- 下一步：`plan-reviewer` 独立审查 → 用户门禁 2 确认 → Phase 3

## 目标

用户 2026-10-20 反馈：目录应当是**树形**、**点击跳转**、**条数多可滑动**、**从左边弹出**。

现状差距：

| 对象 | 现有数据 | 能否直接做树 |
|---|---|---|
| PDF | `PdfOutlineItem(title, pageIndex, children)` 已是树，但 `flatten()` 拍平后用全角空格缩进塞进 `AlertDialog` | ✅ 数据就绪，只需换 UI |
| EPUB | `EpubParser.parseNav` 用 `descendants(nav, "a")` 把 `<ol><li>` 嵌套**拍平**；`parseNcx` 对 `<navPoint>` 同样拍平；`EpubBook.chapters` 是 spine 顺序的扁平列表 | ❌ 必须改解析层保留层级 |

两者当前都用 `AlertDialog` 居中弹窗（`setSingleChoiceItems`），无法折叠、层级靠空格伪饰。

## 设计

### 0 共同约束
- **零新增依赖**（M10.8 的 pdfbox 例外不外扩）。
- **不改 `EpubBook.chapters` 的既有算法**：它是阅读分页与进度的基础设施（721 例单测覆盖）。新增 `tocTree` 与之并存，目录树只用于展示。
- 不改 M10.5 归一化坐标、M10.6 章内偏移、M10.8 浮层 padding 联动等既有不变量。

### 1 不用 `DrawerLayout`，用自定义 overlay 抽屉
`DrawerLayout` 自带**边缘横向滑动手势**，会与横向阅读的翻页滑动抢事件；锁死手势又失去使用它的意义。故自实现：根容器内左侧面板 + `translationX` 滑入/滑出 + 半透明遮罩，**不提供手势打开**（顶栏「目录」按钮一步可达）。

### 2 数据层

新增 `reader/TocNode.kt`：

```kotlin
/** 目录树节点（EPUB 章节树与 PDF 书签树的统一模型）。 */
internal data class TocNode(
    val title: String,
    /**
     * 跳转目标（EPUB）：**已归一化的 epub 根相对路径**（如 `OEBPS/text/ch1.xhtml`），
     * 由 [EpubParser.parseNavTree] / [EpubParser.parseNcxTree] 在解析时用**文档自身所在目录**
     * （nav / ncx 文件所在的目录）作 base 归一化。因此可直接与 `EpubChapter.href` 比较；
     * 纯容器节点（`<li>` 内无 `<a>`）为 null；PDF 恒为 null。
     */
    val href: String? = null,
    /** 跳转目标页（PDF 用；EPUB 恒 -1）。 */
    val pageIndex: Int = -1,
    val children: List<TocNode> = emptyList(),
)
```

`EpubParser` 改动（**最小回归风险策略**）：
- 新增 `parseNavTree(navXml: String, baseDir: String): List<TocNode>`：保留 `<nav><ol><li>` 嵌套。
  - **href 归一化**：`<a href="…">` 的原始值**相对 nav 文档自身所在目录**，故用
    `resolvePathFrom(baseDir, rawHref)` 就地归一化为 epub 根路径后再存入 `TocNode.href`。
    `baseDir` 由调用方（`EpubParser.parse`）传入 nav 文档所在目录。
  - **标题与 href 同源**：都取 `<li>` 子树中**第一个** `<a>`（`descendants(li, "a").firstOrNull()`，
    不限定直接子节点——既有 `parseNav` 用 `descendants(nav, "a")` 全后代遍历，限定直接子节点会漏掉
    `<li><span><a>` 这类写法）。
  - **无 `<a>` 的 `<li>`**：`href = null`、`title = ""`（占位文案统一在 `TocRows` 层注入，解析层不硬编码 UI 文案）。
- 新增 `parseNcxTree(ncxXml: String, baseDir: String): List<TocNode>`：保留 `<navPoint>` 嵌套
  （`navLabel/text` + `content/@src`），`content/@src` 同样用 `resolvePathFrom(baseDir, src)` 归一化。
  无 `content` 的 `navPoint` → `href = null`、`title` 取其 `text`。
- **`parseNav` / `parseNcx` 保持实现与输出完全不变（一行都不改）**。两条独立支路各自维护：
  既有扁平解析继续服务 `chapters` 的标题匹配（分页与进度的基础），新树形解析只服务目录抽屉。
  **不要**把 `parseNav` 改成「先 tree 再拍平」——`descendants(nav, "a")` 的全后代顺序与
  「树前序遍历 + 每 `<li>` 取首个 a」不等价，改写会破坏既有测试与章节标题匹配。
- `EpubParser.parse()` 里计算两个 base 并传入：
  - `navDir` = `resolvePathFrom(opfDir, <nav manifest item 的 href>)` 的父目录
  - `ncxDir` = 同理（NCX item）
  - 两者都取不到时（该书的 nav/NCX 缺失）→ 对应 tree 为 `emptyList()`
- `EpubBook` 新增字段 `tocTree: List<TocNode> = emptyList()`；`parse()` 里填入
- 父节点 href 可能指向「不存在的页」（卷标题等），允许 `href` 存在但映射不到 spine → 该节点不可跳转（见 T2）

### 3 行模型与折叠（纯函数，可单测）

`reader/TocRow.kt`（新）：

```kotlin
/** 目录抽屉的一行。 */
internal data class TocRow(
    val title: String,
    /** 跳转目标（EPUB 章节索引 / PDF 页索引）；-1 表示该项是纯容器，不可跳转。 */
    val targetIndex: Int,
    val depth: Int,
    val hasChildren: Boolean,
    val expanded: Boolean,
    /**
     * 展开状态用的稳定标识——**必须对「含容器节点在内的每一个节点」唯一**，否则会串扰。
     *
     * 不能用裸 href：① 容器节点（`<li>` 无 `<a>`）的 href 为 null，会让所有卷标题共用同一个 id，
     * 展开一个卷时另一个卷被连带展开；② `text/ch1.xhtml#sec1` 与 `#sec2` 去 fragment 后同 href，
     * 同文件内的多个锚点会互相串扰。
     * 故用**树路径**：DFS 兄弟序号拼接（如 `"0/1/2"`），会话内稳定且天然唯一；PDF 同理。
     */
    val id: String,
)

internal object TocRows {
    /** EPUB：tocTree + chapters → 行列表（`TocNode.href` 已在解析时归一化，可直接比较）。 */
    fun forEpub(tree: List<TocNode>, chapters: List<EpubChapter>, missingTitle: String): List<TocRow>
    /** EPUB 回退：tocTree 为空时用扁平 chapters，每章一行（[missingTitle] 用于空标题占位）。 */
    fun forEpubFlat(chapters: List<EpubChapter>, missingTitle: String): List<TocRow>
    /** PDF：PdfOutlineItem 树 → 行列表（pageIndex 直接可用）。 */
    fun forPdf(tree: List<PdfOutlineItem>): List<TocRow>
}

internal object TocFlatten {
    /** 按展开集合把树拍平成「当前可见行」（折叠的子树不出现）。 */
    fun visibleRows(rows: List<TocRow>, expanded: Set<String>): List<TocRow>
}
```

- `forEpub` 的 href → index：`TocNode.href` 已是 epub 根相对路径（解析层用 nav 文档目录归一化），
  直接与 `chapters[i].href` 精确比较；`href == null`（纯容器）或找不到 → `targetIndex = -1`
  （容器行：不可跳转，但可折叠）。
- **不要**在这里再传 `opfDir` / `navDir` 做二次归一化：base 已在对的地方用过一次，
  二次归一化会把 `OEBPS/text/ch1.xhtml` 错拼成 `OEBPS/OEBPS/text/ch1.xhtml`。
- `missingTitle`（`forEpub` 与 `forEpubFlat` 都收）：节点标题为空（容器节点）时用它占位；
  由 Activity 传 `getString(R.string.reader_chapter_untitled)`，纯函数里拿不到资源。
- `visibleRows`：DFS，父节点出现后若 `expanded.contains(id)` 才递归子节点
- 默认展开策略：**只展开「当前章节的所有祖先」**，其余折叠

### 4 UI 层

> 两个新类都放 **`com.seshat.app.reader`** 包（与阅读器其它类同包，便于 `internal` 可见性）；
> **不要**放进 `com.seshat.app.ui`（那里是书架/笔记等 Fragment）。

`reader/TocDrawer.kt`（新）：一个挂载在 Activity 根 `FrameLayout` 上的抽屉，结构由代码构建（避免两处布局重复）：
- 遮罩 `View`（`#99000000`，点击 `hide()`）
- 面板：`LinearLayout(vertical)`，宽 `min(320dp, 屏宽 * 0.78)`，`layout_gravity="start"`，底色 `#FFFAFAFA`
  - 顶栏：标题「目录」+ 右侧「×」
  - `RecyclerView`（`LinearLayoutManager`，`clipToPadding = false`）
- `show(rows, currentTargetIndex)`：设置数据 → 展开当前项祖先 → `translateX(-width)` → `animate().translationX(0)`；`hide()` 反向
- **首次打开必须等测量**：面板尚未布局时 `width == 0`，`translationX = -0` 会让抽屉「闪出」而没有滑入动画。
  故 `show()` 里先 `panel.post { panel.translationX = -panel.width.toFloat(); panel.animate()... }`，
  或用 `panel.doOnLayout { }` 设置初始位移后再动画；`hide()` 用当前 `panel.width` 即可。
- `isShowing` / `hide()`；返回键由 Activity 的 `OnBackPressedDispatcher` 拦截（抽屉开着时先关抽屉）
- 抽屉打开时**不**触碰阅读区 padding（它是覆盖层，不是浮层）
- **面板必须自己消费触摸**：面板 `LinearLayout` 默认不消费，点面板空白（非列表项）会穿透到下层遮罩
  触发 `hide()`。故面板 `isClickable = true`（遮罩同样 `setOnClickListener { hide() }`）。
- **addView 顺序必须是「遮罩 → 面板」**（面板在上层）；反过来会让面板被遮罩盖住、点不动。

`reader/TocAdapter.kt`（新）：`RecyclerView.Adapter`
- 行布局由代码构建：`LinearLayout(horizontal)` = 缩进占位 `View(width = depth * 16dp)` + 箭头 `TextView`（`▸`/`▾`，`hasChildren` 时可见）+ 标题 `TextView`
- 点箭头 → `onToggle(id)`；点标题 → `onPick(targetIndex)`（`targetIndex < 0` 时只切换展开）
- 当前项高亮：`setCurrent(index)` + `notifyItemChanged`

### 5 接线

- `EpubReaderActivity.showToc()`：改为 `tocDrawer.show(TocRows.forEpub(book.tocTree, book.chapters, getString(R.string.reader_chapter_untitled)), currentChapterIndex())`；`tocTree` 为空时回退「扁平 chapters」（`TocRows.forEpubFlat(chapters, getString(R.string.reader_chapter_untitled))`，一行一节，保持旧行为）；**不再传 `book.opfDir`**
  - 两个 `missingTitle` 都由 Activity 传 `getString(R.string.reader_chapter_untitled)`（纯函数里拿不到资源；`forEpub` 也需要，因为容器节点可能标题为空）
- `PdfReaderActivity.showPdfToc()`：改为 `tocDrawer.show(TocRows.forPdf(outline), firstVisiblePage())`；outline 为空仍回退页码目录（现有 `pageDirectory` 行为保留）
- 两个 Activity 的 `toggleChrome()`：浮层隐藏时若抽屉开着，一并 `hide()`（避免抽屉悬空）
- `onBackPressed`：抽屉开着 → 关抽屉并 `finish()` 抑制

## 注意事项

- **`chapters` 不得改算法**：它是分页与进度的基础，只允许新增 `tocTree` 支路。
- **`parseNav` / `parseNcx` 的签名与输出必须逐字节一致**（既有测试是回归闸门）。
- **抽屉不是浮层**：不要复用 `applyContentPadding` / `ReaderChrome`，也不要在抽屉开合时改阅读区 padding。
- **不要给抽屉加边缘滑动手势**：会与横向翻页抢事件。
- 父节点 `targetIndex = -1` 时，点击行为是「折叠/展开」而不是「跳第一页」（M10.8 的 `pageIndex < 0` 教训）。
- EPUB 的 `<li>` 可能没有直接子 `<a>`（只有嵌套 `<ol>`）：解析层只置 `href = null` / `title = ""`，
  占位文案（`missingTitle`）统一在 `TocRows` 层注入，**不要在解析层硬编码 UI 文案**。
- **旋转屏**：两个阅读器 Activity 未声明 `configChanges`（保持既有行为），旋转会重建 Activity，
  目录抽屉的展开状态与滚动位置会丢失（需重新点「目录」）。属可接受的已知限制，不在本次处理。
