## 背景

notes 系统路线图 M11 需要在 Emacs 阅读器上实现「选中文本 → 翻译/LLM、区域框选 → OCR」。
用户已裁决走方案 B：**扩展 emacs-reader（自研 C 模块）**，放弃 pdf-tools/nov.el 双引擎。
emacs-reader 现状为纯图像渲染（无文本层、选区被 remap 为 `ignore`），故先做本 PoC 验证技术可行性。

本 PoC 的唯一目的：验证「能否从 emacs-reader 取到某页面某矩形内的文字」。

## 目标

1. 证明 MuPDF 文本提取可在 emacs-reader 的架构（DocState / EmacsWinState / 线程池 / fz_context）内工作；
2. 实测并记录「屏幕像素坐标 → 页面坐标」的换算公式与偏差（限定 rotate=0）；
3. 若不可行，尽早证伪，以便回退方案 A（pdf-tools + nov.el）。

## 设计

### 渲染链路（事实依据）

`render/render-core.c:158`（ctm）与 `:184-185`（frame_scale 除法）：

```
ctm = fz_transform_page(page->bbox, win_state->resolution, win_state->rotate)
pixmap = fz_new_pixmap_from_display_list(display_list, ctm, ...)
local_imgw/h = pixmap_width/height / frame_scale      // Emacs 显示的像素尺寸
```

### 坐标换算策略

- C 函数接收的是**页面坐标**（PDF point 空间）；
- 换算推导：`页面坐标 = ctm⁻¹ · (屏幕像素 × frame_scale)`；
- **本 PoC 限定 `rotate = 0`**：此时 ctm 为纯缩放/平移，elisp 侧可用 `reader-current-doc-scale-value` + `window-vscroll`/`window-hscroll` + frame_scale 复原；
- `rotate ≠ 0` 时，rotate 只存在于 C 侧 `EmacsWinState`（elisp 侧无读取途径），换算需下沉到 C 侧 —— **列入 M11.2，不在本 PoC 范围**。

### 新增模块函数（render-core.c / render-core.h）

| 注册名 | C 函数 | 参数 | 返回 |
|---|---|---|---|
| `reader-dyn--page-text` | `emacs_page_text` | `page`（整数，缺省当前页） | 整页纯文本 |
| `reader-dyn--text-in-rect` | `emacs_text_in_rect` | `page x0 y0 x1 y1`（页面坐标，浮点） | 矩形内文本 |

实现要点：

- **取状态**：`get_reader_current_state(env, &doc_state, &win_state, &overlay)`（`elisp-helpers.c:616`）——一次取齐 DocState 与 EmacsWinState（「缺省当前页」需要 `win_state->current_page_number`，`resolution`/`rotate` 亦在 win_state）；
- 页面：`fz_load_page(doc_state->ctx, doc_state->doc, page)`；
- 文本层：`fz_new_stext_page_from_page(ctx, page, NULL)`；
- **整页文本**：`buf = fz_new_buffer(ctx, 1024)` → `out = fz_new_output_with_buffer(ctx, buf)` → `fz_print_stext_page_as_text(ctx, out, stext_page)` → 从 buffer 取字节转字符串；
- **矩形内文本**：遍历 `stext->first_block`（仅 `FZ_STEXT_BLOCK_TEXT`）→ line → char，用 `fz_rect_from_quad(ch->quad)` 与给定矩形求交，命中则追加 `ch->c`（UTF-8 编码）；
- **并发策略**：仿 `load_page_dl`，用 `fz_clone_context(doc_state->ctx)` 克隆上下文执行文本提取（克隆共享同一 locks，正是 MuPDF 的多线程模型）。注意：`g_mupdf_mutex[FZ_LOCK_MAX]` 是 MuPDF 内部 locks context 的锁集合（由 `fz_context` 按 lock type 调用），**不是函数级互斥量**，**不得**直接 `pthread_mutex_lock` 它；
- **资源释放**（分两处）：`fz_always` 内按序 `fz_drop_stext_page` → `fz_close_output` → `fz_drop_output` → `fz_drop_page`；从 buffer 取出字节转成字符串**之后**（`fz_try`/`fz_catch` 结构之外）再 `fz_drop_buffer`；
- **入口检查**：函数入口若 `doc_state->is_reloading` 或 `win_state->closing` 为真，直接返回 `EMACS_NIL`（避免 reload/close 窗口期 use-after-free）；
- **错误处理**：`fz_try` / `fz_catch`，失败时 `emacs_message` 并返回 `EMACS_NIL`；
- **空文本层**（扫描件）：返回 `nil`（属预期，见「注意事项」）；
- **注册**：在 `emacs_module_init` 中用 `register_module_func(...)` 登记。

### elisp 验证层（reader.el，只增不改既有函数）

- `reader-poc-dump-page-text`：打印当前页文本；
- `reader-poc-text-in-rect`：交互式读取参数，打印区域文本。

（两个新命令的 docstring 必须满足 checkdoc：首行完整句、参数在 docstring 中出现等。）

## 注意事项

- **只增不改**：不得修改既有渲染路径与既有 elisp 函数；
- **并发**：文本提取用 `fz_clone_context`（仿 `load_page_dl`）；不得把 `g_mupdf_mutex` 当函数级互斥量；
- **坐标空间**：C 函数接收页面坐标；屏幕坐标换算在 elisp 侧完成，本 PoC 限定 `rotate=0`；
- **扫描件界定**：本 PoC 仅验证**文本型 PDF**；无文本层的扫描件返回 `nil` 属预期，OCR 不在本 PoC 范围；
- **矩形内文本**：PoC 阶段不保留换行结构（连续拼接命中字符），不影响「能否取到文字」的验证目标，行结构完善列入 M11.2；
- **编码**：`fz_stext_char.c` 为 Unicode 码点，需 UTF-8 编码后交给 `env->make_string`；
- **回滚**：T1 记录的 commit 即回滚点；PoC 失败可还原；
- **不改 straight 配置**：不修改 init-reader.el 的 recipe 与 lockfile。

## 结论

**判定：可行 ✅**（2026-10-12，在独立 `emacs --batch -Q` 进程中实测，未干扰运行中的 Emacs）

### 实测证据

- 测试件：新生成的最小 PDF（3 行文本，A4 595×842pt）；**用户书库 `/home/thomas/WorkSpace/e-book/` 的 6 个候选 PDF 经 `pdftotext` 实测均为扫描件、无文本层**。
- 整页文本：`reader-dyn--page-text` 输出与 `pdftotext` 对照**逐字一致**（含行间空行）。
- 矩形取文：`reader-dyn--text-in-rect` 坐标命中精确 —— `(50,100,545,140)` 仅返回顶部行，`(40,400,560,460)` 仅返回中间行；整页矩形返回全部三行（不保留换行）。
- 坐标语义：**页面坐标，原点左上，y 向下**；顶部文字行位于距页顶 112pt，与矩形 y∈[100,140] 吻合。
- 无文本层文档：返回 `nil` 并提示 `No text layer found (scanned document?).`。
- 全程无崩溃。

### 已知问题与修复

- **整数参数被拒**：C 层 `env->extract_float` 不接受整数，`(reader-dyn--text-in-rect 0 50 100 545 140)` 报 `(wrong-type-argument floatp 50)`。已在 `reader.el` 的命令层统一转 `float` 修复。

### 未完成项（移入 M11.2）

- **屏幕坐标 → 页面坐标的换算公式未实测**：本 PoC 用 `--batch` 验证，无真实窗口交互，只验证了页面坐标语义本身；实际换算偏差（含 `rotate≠0`）需在真实窗口补测。

### 对后续的影响

- 路线 B（自研 C 模块）**未被证伪**，可继续 M11.2。
- 用户书库以扫描件为主 ⇒ **区域框选 OCR 是刚需**，M12 的 OCR 优先级应上调。
